Section 1

1What Is This System?

In one sentence: you tell a Telegram bot what you worked on, it also counts your GitHub commits, keeps a daily streak on a public web page, and every night writes a short post that goes to Bluesky only if you approve it.

What it does

  • Logs your work: send /log fixed the login bug 1.5h. Hours are optional.
  • Counts commits too: commits you push to the repos listed in config.json are added on their own. Bot and CI commits don't count.
  • Keeps a streak in India time (IST): any day with at least one entry counts. The streak stays alive until midnight IST.
  • Reminds you at 9 PM IST if nothing is logged yet and your streak is at risk.
  • Drafts a post at 10:30 PM IST: AI turns the day's notes and commits into a short update, e.g. "Day 12 of shipping daily 🚢 …". You get Approve & post, Skip and Rewrite buttons.
  • Shows it publicly: a page with your streak, a 12-month heatmap and a timeline of every day.

Section 2

2How the Streak Is Counted

The rule is simple: a day counts if it has at least one entry, and the streak is the number of days in a row, counted in India Standard Time.

The rules

  1. One entry is enough. A /log message or one commit makes the day count. Five entries in one day still count as one day.
  2. Days are IST days. GitHub stores commit times in UTC. The app moves them to IST first, so a commit at 19:00 UTC on 3 Oct counts for 4 Oct (00:30 IST).
  3. Today is a grace day. If you haven't logged yet today, yesterday's streak is still shown, marked "at risk", until midnight IST.
  4. A missed day resets it. The current streak goes back to 0. Your longest streak is kept.
  5. Only real work counts. Commits from bots (names ending in [bot], GitHub Actions, Dependabot), merge commits and messages with [skip ci] are ignored.

A worked example (today is 4 October)

DateEntriesCounts?
1 Octnone✘ gap
2 Oct/log wrote the streak tests 2h✔
3 Oct2 commits to a tracked repo✔ (one day)
4 Oct, 8 PMnothing yetgrace day

At 8 PM the page shows a 2-day streak, at risk. At 9 PM IST the bot sends "Streak at risk!". If you send /log fixed the heatmap colours 1h before midnight, the reply is "✅ Logged (1h) … 🔥 Day 3 — streak kept alive!".

Hours are optional 2h, 1.5 hours and 45m are read as hours (0.75 for 45m). Numbers that aren't hours, like "read 3 chapters", stay in the text.
Section 3

3System Architecture

Every piece involved and how they connect. Each tool is explained in Section 6, and every technical word is in the Glossary.

In words

  1. You send messages to the bot and push code to your repos as usual.
  2. Every 15 minutes GitHub Actions starts a small Python job, the tick. It reads new Telegram messages, pulls new commits, sends the reminder or draft if it's time, and rebuilds the page data.
  3. Everything is saved as JSON files in data\. The job commits them back to the repo, so the repo itself is the database.
  4. Drafts are written by Gemini; if that fails, Groq; if both fail, a plain template.
  5. When you press Approve, the post goes to Bluesky. The page is redeployed to GitHub Pages whenever the data changed.
Section 4

4How It Works, Step by Step

4.1 — One tick (every 15 minutes)

  1. Telegram: fetch messages and button presses since the last one handled (the position is saved in data\state.json).
  2. Commits: ask GitHub for commits since the last sync, minus 2 days of overlap to catch late pushes. Already-known commits are skipped.
  3. Jobs: after 21:00 IST with nothing logged → reminder (once a day). After 22:30 IST with something logged and no draft yet → draft.
  4. Page: rebuild docs\data.json. If anything changed, commit and deploy the page.

4.2 — Writing the draft

  1. The day's notes and commits are listed for the AI, with the total hours.
  2. The AI is told: one update, at most 200 characters, first person, concrete, no hashtags, no hype words.
  3. The app adds "Day N of shipping daily 🚢" in front, then #buildinpublic and the page link if they fit in Bluesky's 300-character limit.

4.3 — Approving it

ButtonWhat happens
✅ Approve & postPosts to Bluesky and shows the link. In dry-run it is only marked "approved".
⏭ SkipMarked skipped. Nothing is posted. The day still counts in the streak.
🔄 RewriteAsks the AI again and replaces the text in the same message.

If posting fails, the bot says why and the draft stays pending, so you can press Approve again.

Why these choices?

  • No packages: nothing to install or update, and nothing breaks when a library changes.
  • GitHub Actions instead of a server: free and always on. The cost is a slower bot (up to 15 minutes).
  • JSON in the repo instead of a database: the log is public anyway, and git keeps the full history.
  • Bluesky: its API is free and allows posting with an app password. X and LinkedIn don't offer that for free.

Section 8

8Troubleshooting & FAQ

The bot doesn't answer

Online it answers within about 15 minutes, and GitHub's timer can run late. Check Actions for a red run. On the PC, dev.py must be running and show "Bot: listening".

Some messages get answered, others vanish

dev.py and Actions are both reading the same bot. Stop dev.py, or use dev.py --page-only.

Bot says "Your chat id is …" to every message

TELEGRAM_CHAT_ID isn't set. Put that number in .env (and the Actions secret) and restart.

My commits don't show up

Check the repo is in github_repos as owner/repo and github_author is your GitHub username. Private repos need GH_TOKEN. Merge commits and [skip ci] commits never count. Run C:\Python314\python -m shiplog sync to see what it finds.

A commit counted for the wrong day

Days are IST. A commit after midnight IST counts for the next day, even if it was still evening in UTC.

The draft says "template" instead of gemini or groq

Both AI services failed (wrong key, limit reached, or retired model). The template draft still works. Check the keys and model names.

Approve says "Approved (not posted…)"

Dry-run is on or Bluesky isn't set up. Set BLUESKY_DRY_RUN = 0 and both Bluesky secrets.

"Bluesky post failed"

Usually a wrong handle or app password. The draft stays pending; fix the secret and press Approve again.

The page shows "Couldn't load data.json"

Open it through http://localhost:8107 or the Pages address, not by double-clicking the file.
